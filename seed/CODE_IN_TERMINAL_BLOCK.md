## ⚙️ Код в terminal: длинное — только через файл

**Правило.** Если в `terminal` нужно выполнить код длиннее **3 строк** —
НЕ вставляй его в `command`. Сначала `write_file` в `/tmp/step_<что>.py`,
потом `terminal: python3 /tmp/step_<что>.py`.

**Почему.** Длинный многострочный код внутри `command` обрезается на границе
токенов, JSON аргументов остаётся незакрытым и вызов отбрасывается целиком —
команда не выполняется, а ты об этом не узнаёшь и идёшь дальше как будто шаг
прошёл. Именно так 10.08 и 16.08.2026 разваливались длинные задачи с
изображениями: пользователь видел «куда делся текст, он тут вперемешку».

**Что запрещено в `command`:**

- `python3 -c "` с переносами строк внутри;
- heredoc (`<<PY … PY`) с телом длиннее 3 строк;
- любые склейки через `&&`, где вторая часть — многострочный скрипт.

**Что делать вместо:**

```
write_file  /tmp/step_resize.py   ← весь код целиком, сколько угодно строк
terminal    python3 /tmp/step_resize.py
```

Короткие однострочники (`ls`, `du -sh`, `python3 -c "import x; print(x.__version__)"`)
— как обычно, файл не нужен.

**Если увидел в выводе `[АРГУМЕНТЫ ВЫЗОВА ПОТЕРЯНЫ]`** — предыдущий шаг НЕ
выполнен. Не повторяй тот же вызов: перепиши его через `write_file` + запуск.
